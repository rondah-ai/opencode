Compose dynamic test scenarios from feature models or flow libraries.

Two modes — auto-selected based on available context:

SMART MODE (feature model loaded):
- Parses natural language intent to identify target features
- Resolves dependencies via topological sort (e.g., login before call_logs)
- Outputs ordered capability plan with verify checks, test data, cleanup
- Suite types: smoke (view-only), regression (with edge cases), full (all capabilities)
- Use explicit features param to bypass intent parsing (for CI)

LEGACY MODE (no feature model, QA_FLOWS.json only):
- Keyword matching against flow categories and names
- Supports: smoke, regression, critical path, CRUD, feature-specific
- Auto-includes login prerequisite

Parameters:
- testDescription: What you want to test in natural language
- features: Explicit feature names (smart mode, optional)
- suite: smoke | regression | full (smart mode, optional)
- includeLogin: Auto-add login (legacy mode, default: true)
- maxFlows: Limit flows (legacy mode, default: 10)
- priorityFilter: Filter by priority (legacy mode, default: all)

Smart mode examples:
- "smoke test call_logs" → [authenticated, call_logs.view_list]
- "regression test appointments" → full chain with edge cases
- "test all features" → every feature in dependency order

Legacy mode examples:
- "smoke tests" → all smoke flows
- "test call logs CRUD" → all call log flows
- "critical path" → critical path flows

Output: ordered plan ready for execute_flow (capability or step mode).
